# pr-marin: one feature, one PR, into marin-community

Luke's rules (2026-09-10): new work lives on his `lukedhlee/*` branches in the **marin-community** repos, never the
personal fork. A PR is one reviewable idea, cut fresh from `upstream/main`, and it is opened only when he says so.
Never write that anything was generated by AI: no `Co-Authored-By: Claude`, no `Claude-Session:` trailer, no
"Generated with Claude Code" footer, anywhere. Grep before every commit and before `gh pr create`.

## Procedure

1. **Pick the commits.** From the feature branch, list the commits of the one idea:
   `git log --format='%h %s' upstream/main..HEAD -- <files>`. One theme, roughly 200 to 600 changed lines. Anything
   contentious (a policy change, an experiment knob) goes in its own PR or stays out.
2. **Cut a fresh branch from main** in its own worktree, cherry-pick with `-x`, and see what it drags in:
   ```bash
   git -C <feature-worktree> worktree add -b lukedhlee/<slug> /Users/lukedhlee/harbor-wt/<slug> upstream/main
   git -C /Users/lukedhlee/harbor-wt/<slug> cherry-pick -x <shas>
   ```
   Conflicts mean a hidden dependency: either include the base commit it needs or rewrite the diff onto main.
   A conflict mid-sequence followed by `git cherry-pick --abort` resets the branch to where the sequence started,
   dropping every commit already applied. Always check `git log --oneline upstream/main..HEAD` before lint, tests or push.
3. **Prove it.** ruff check + ruff format --check on the touched files; the full unit suite for harbor
   (`PYTHONPATH=src /Users/lukedhlee/harbor/.venv/bin/python -m pytest -q -p no:cacheprovider tests/unit --ignore=tests/unit/test_archive.py`)
   or `tests/cpu` + `cloud/iris/tests` for MarinSkyRL (`.venv/bin/python` in the worktree). Put the numbers in the body.
4. **Push to marin-community** with `-u`: harbor worktrees call that remote `upstream`, the MarinSkyRL worktree calls it
   `origin`. Check `git ls-remote --heads <remote> lukedhlee/<slug>` afterwards.
5. **Draft the body** into `ai_memory/active/<project>/pr_drafts/<slug>.md` in the house style below, then open it
   for him to edit: `cursor ai_memory/active/<project>/pr_drafts/<slug>.md` (also `pbcopy` it). He edits in Cursor;
   re-read the file before opening the PR so his edits are what ships.
6. **Open only on his explicit go** ("open it"):
   ```bash
   gh pr create --repo marin-community/<repo> --base main --head lukedhlee/<slug> --title "<title>" --body-file <body>
   ```
   `grep -c -i "claude\|co-authored\|generated with" <body>` must print 0 first. `gh pr create` prints the URL:
   open it in his browser right away (`open <url>`, run with the Bash sandbox disabled: inside the sandbox `open`
   exits 0 and shows nothing) so he sees the PR as it went up, then record the PR number in the
   project's pr_queue / findings note and the migration memory.
7. **Land the same change on the running feature branch additively** (cherry-pick, or revert of the old version), never
   by rewriting its history.

## House style (harbor#122, #124)

Title: `[<area>] <what changes, plain words>`; name the feature it belongs to (TITO, terminus-2, tmux) in the title.

Body, in this order, headings in bold:

- **First line, bold: the impact.** What breaks or costs, for whom, in one sentence a busy reviewer understands
  without context. Then one or two sentences with the measured effect (before → after numbers).
- `Related: #a, #b, other-repo#c.` links to the PRs it builds on or pairs with.
- **What goes wrong.** The mechanism, in plain words, no code identifiers unless the reader has to go there.
- **The fix.** Two to four bullets, each one decision.
- **Measured.** Same setup before and after, counts not percentages when the population is small.
- **Tests.** File names and the suite count.
- Background, history, and how it was found go under their own heading at the end, or not at all.

Compress the idea, not the words: fewer sentences that each carry one idea, no jargon Luke would have to look up
(no "surcharge", no "overflow recovery" without saying what it is). No em-dash chains, no parentheses stacking caveats.

## Checklist before `gh pr create`

- [ ] branch is on marin-community, cut from current `upstream/main`, cherry-picks carry `-x`
- [ ] full suite green, numbers in the body
- [ ] body file was opened in Cursor and re-read after Luke's edits; first line is the impact, title names the feature
- [ ] zero matches for claude / co-authored / generated with, in every commit message and the body
- [ ] Luke said "open it" for this PR specifically
- [ ] after `gh pr create`: `open <url>` in the browser, then record the number
